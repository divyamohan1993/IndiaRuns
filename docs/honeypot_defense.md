# Honeypot defense

The pool contains planted "honeypot" profiles — structurally impossible candidates
designed to fool a naive ranker. The briefing expects roughly 80 of them, and the metric
DQs any submission with more than 10 honeypots in its top-100. ATLAS treats honeypot
exclusion as a hard, deterministic, defense-in-depth gate and ships **0 honeypots in the
top-100 and 0 in the top-10** over the real full pool.

The defense rests on one discipline: **only structural impossibilities are traps.**
Anything that is merely unusual, or merely "no data", is not.

---

## The data correction that defines the clean-201 set

An early artifact (`likely_honeypots.json`) over-counted by mixing in two *noisy*
signatures that fire on ordinary data:

- `skill_duration_exceeds_career` — **9,231 hits**
- `edu_degree_order_impossible` — **4,715 hits**

These are not the ~80 planted traps; they are routine data noise. Using a "≥1 signature"
union that includes them would exclude thousands of legitimate candidates. ATLAS therefore
**demotes both to soft features** (a small negative contribution in Group E; they never
gate to −∞ on their own) and regenerates the hard-exclude set from the
**high-precision structural-impossibility signatures only**.

The smoking gun behind the core cluster: `expert` proficiency is only **0.137%** of all
skills in the pool, and **99,800 candidates claim zero expert skills** — yet a distinct
cluster of **167 candidates claims 5–12 expert skills each**. A real person essentially
never does this. Moreover, **167 of the 201 hard-flagged candidates carry AI keywords**:
the honeypots are deliberately AI-keyword-rich traps built to fool a keyword ranker.

---

## The clean 201-id hard-exclude set

Regenerated by `precompute/build_honeypots.py` → `artifacts/honeypot_excludes.json` from
the clean signatures only (never from the polluted `ge1`/`ge2` keys):

| Signature | Count | Rationale |
|---|---|---|
| `too_many_experts` (≥5 expert skills) | **167** | A real person essentially never claims 5–12 expert skills. The core trap cluster. |
| `career_sum_exceeds_yoe` (Σ tenure > 1.5×YOE·12) | **24** | Experience math impossible. |
| `expert_zero_duration` (expert proficiency, 0/absent duration) | **21** | Claimed mastery with zero time used. |
| `tenure_exceeds_company_age` (tenure > company-age proxy + 18mo) | **3** | 8 years at a 3-year-old company. |
| `career_span_exceeds_yoe` (earliest start → now > YOE + 3 yrs) | **3** | Timeline impossible. |
| date/chronology guards (`edu_end_before_start`, `career_end_before_start`, `current_with_enddate`, `tenure_gt_360`, `*_future`, `duration_span_mismatch`) | **0 today** | Kept as cheap guards; the hidden pool may differ. |

**Clean deduplicated union = exactly 201 candidate_ids.** Symmetric-difference vs the
independent probe's clean set = 0. 201 is a safe **superset** of the ~80 planted traps at
negligible recall cost (the extra ids are non-fits anyway), which makes the
">10-in-top-100" DQ mathematically near-impossible from this source.

## Three layers (all deterministic, all on the rank path)

**Layer 1 — frozen hard-exclude gate (`final = −∞`).** Any id in the clean-201 set is
gated to negative infinity before sorting, so it can never reach the top-100.

**Layer 2 — live re-verify of survivors.** `rank.py` re-runs the clean structural checks
(pure-python, microseconds per candidate) on every candidate that survives into the
**top-300 by margin** and gates any that trip ≥1 clean signature. This is robust even if
the hidden grading pool reorders ids or a trap somehow scored high and was not in the
frozen list. Salary inversion is explicitly excluded from these checks.

**Layer 3 — top-10 paranoia.** Each top-10 slot must additionally satisfy: not in the
exclude set, zero clean signatures, **and** at least one real career-evidence hit
(`Σ evid_* > 0` — a genuine shipper, not a flag-free phantom). Any failing slot is swapped
for the next qualifying candidate, protecting NDCG@10 and P@10 with margin.

**Independent LLM gate (Plane A).** The offline shortlist re-rank also emits
`disqualifier_flags`; a shortlisted id flagged impossible by the LLM is down-capped. Two
independent layers — deterministic and LLM — both guard the top.

See the layered diagram in [`architecture.md`](architecture.md#4-honeypot-defense-layers).

## The two critical non-checks (what we deliberately do NOT flag)

**Salary inversion `min > max` — NOT a trap.** It fires on **18,865 candidates (18.9%)** —
a deliberate dataset norm matching the briefing's "~19% inverted". Excluding it would nuke
a fifth of the pool. It is not a honeypot signature and is not even a feature.

**The `-1` sentinels — never penalize.** `github_activity_score == -1` (64.6%) and
`offer_acceptance_rate == -1` (59.6%) mean "no data", not impossibility. They contribute
exactly 0 to the behavioral multiplier (unit-tested: flipping either to −1 must never
decrease a candidate's score) and are never honeypot signals.

## Verification

`scripts/assert_no_honeypots.py` cross-checks the frozen clean-201 set AND a live re-run of
the clean structural checks over the ranked ids:

```
ranked=100 frozen_set=201 honeypots_in_top100=0 in_top10=0
OK: 0 honeypots in top-100.    (exit 0)
```

`tests/test_gate_blocks_honeypots.py` and `tests/test_salary_inversion_not_flagged.py`
assert the gate behavior and the salary non-check on fixtures. No non-engineering-title
keyword-stuffer (Marketing/HR/Sales) appears anywhere in the top-50 of the real ranking.
